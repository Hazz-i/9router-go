### feat(image): image-in / image-out editing (`/v1/images/edits`) and Kenari vision caps

- New engine route **`POST /v1/images/edits`** (plus the `/images/edits` spelling), OpenAI-compatible multipart: `image` (or `image[]`), optional `mask`, `prompt`, `model`, and the same options the generations path takes (`n`, `size`, `quality`, `background`, `output_format`, `image_detail`). The handler resolves the provider through `ResolveModel` exactly like generations, rewrites the model to the upstream id, and streams the rebuilt multipart to `{base}/v1/images/edits` with the connection's Bearer key — parts are replayed through an `io.Pipe` in their original order and headers, so nothing is buffered whole.
- Upload bound: file parts spool to temp files, text parts cap at 64 KiB, and the request total is capped at **20 MB** with a 413 in the house error shape; `internal/middleware/max_body.go` routes `/images/edits` to `MediaMaxBodySize` so the JSON ceiling does not pre-empt it. `x-connection-id` / `x-provider-connection-id` pinning works as on the other media lanes.
- Any OpenAI-compatible image provider serves the route; Kenari is not special-cased in the handler.
- `providerCapabilities["kenari"]` marks its six image ids `Vision: true, ImageOutput: true`, so `/api/models/caps?provider=kenari` reports image input for them. The shared `gpt-image-*` ids keep their existing global caps for every other provider.
- Dashboard: the image provider page gained **Attach image** — file picker with thumbnail, filename, replace/remove, a 20 MB hint and an inline rejection — and Run now posts multipart to `/v1/images/edits` when a file is attached, JSON to `/v1/images/generations` when not. The response preview renders `data[0].url` or `b64_json` as an image, and the endpoint/curl snippet follows the attachment.

Verified: `go build ./...`, `go vet`, `go test` for media/providers/middleware/handlers (including the fake-upstream multipart assertions, the 413 cap, missing-image 400, unknown-provider passthrough), `bun test src scripts` (659 pass), `bun run build`, svelte-check ratchet (0 unresolved, 77 = baseline), oxlint. Live on a local gateway: `/api/models/caps?provider=kenari` returns `vision: true` for all six, `/v1/images/edits` answers 400 `expected multipart/form-data with an image file part` without a file, and the served bundle carries the attach UI and the edits path.
