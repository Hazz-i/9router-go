### feat(media): add a custom provider to the Text-to-Image lane

- The Image page now offers **Add Custom Image**, the same flow the Embedding page has had: name, model prefix, OpenAI-compatible base URL (`/v1` allowed, so `https://kenari.id/v1` works), and an optional model id for the Check probe. It creates a provider node of type `custom-image`, whose id is the provider id (`custom-image-<prefix-suffix>`) and whose models are typed as `<prefix>/<model>`.
- Credentials: a custom image node maps to the catalog with `noAuth: false`, so its provider page shows the existing Connections card and the operator adds the API key there. The key entered in the create dialog stays what it always was — a one-shot value for the Check button — and the dialog now says so for this variant. Embedding nodes keep their current proxy-only card, unchanged.
- Model ids come from the existing custom-model flow (`POST /api/models/custom` with `type: image`), which the image provider page already reads; no second model editor was added.
- Backend: `custom-image` joins the provider-node id literals (an id may not shadow it), `isCompatibleProviderID` recognises the prefix so `/v1/models` lists the node's own models, and `POST /api/provider-nodes/validate` gained `validateCustomImageNode` — `GET {base}/models` first (auth 401/403 stops there), and only when that answers 404/405 a single `POST {base}/images/generations` with a minimal body. Never retried, never more than one generation.
- Updating such a node strips a trailing `/` and a pasted `/images/generations` from its base URL, mirroring the `/embeddings` strip for embedding nodes, so the route cannot be doubled downstream.
- Model ids are managed on the provider page itself: a `custom-*` media provider now shows **Add** (one or more ids, comma/semicolon/newline) and **Import from /models** next to the Models heading. Both write through the existing custom-model rows with the kind's own type (`image`), so the list the page already renders picks them up immediately. Import is disabled until an active connection exists, because the catalogue read is the connection's key.
- Two pre-existing gaps had to close for that to be true: `GET /api/providers/{id}/models` refused every provider whose id is not `openai-compatible-*` or `anthropic-compatible-*`, which made Import answer "does not support models listing" for any custom node (embedding included); it now accepts any id that resolves to a provider node. And the media page's Add Connection posted `key` where the API reads `apiKey`, so the key it collected was silently dropped — every connection added from a media provider page had no credential.
- The image upstream URL builder already normalised a base ending in `/v1`; that behaviour is now pinned by a table test over bare host, `…/v1` and `…/v1/` bases, asserting the upstream sees exactly `/v1/images/generations` with the connection's Bearer key.
