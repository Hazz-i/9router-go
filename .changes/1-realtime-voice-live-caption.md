### Realtime Voice & Live Caption: routes, browser-socket auth, rate-limit seam, WS model probe (upstream decolua/9router v0.5.105 parity)

- **Realtime voice (`GET/POST /v1/realtime`).** OpenAI Realtime-compatible voice socket, ported from upstream `src/sse/handlers/realtimeVoiceWs.js` + `realtime/*.js`: `session.created` on connect, `input_audio_buffer.append` (JSON and raw binary) → upstream audio, upstream events mapped back with response-id rotation after `response.cancel`, `session.update` before/after setup, and the per-transport adapters (`deepgram` — `Settings` as the first frame with `Authorization: Token`, keep-alive cadence, think-endpoint hop; `gemini` — the Cloud Code live envelope with transcription fields as `generationConfig` siblings and a 125 ms silence heartbeat feeding server VAD). Model/voice/transport resolve through `internal/providers.GetRealtimeConfig` (data-driven: a provider gains or loses realtime by a registry edit, never by a model-name test), and one usage row is written per session, exactly once, before the handler returns.
- **Live caption (`GET/POST /v1/audio/live-transcriptions`).** Ported from upstream `liveCaptionWs.js` with all four backends — `deepgram`, `elevenlabs`, `gemini` and a self-hosted STT endpoint — behind one `context.Context`-propagating session, emitting the `connected` → `ready` → `word` → `final`/`error` frame sequence with per-word timing, and the same `internal/providers.GetCaptionConfig` registry lookup as the voice socket.
- **Dashboard.** `RealtimeVoiceExampleCard.svelte` (Svelte 5 runes) ports upstream `RealtimeVoiceExampleCard.js`: mic → 16-bit PCM → `input_audio_buffer.append`, 24 kHz playback scheduled back to back with barge-in on `input_audio_buffer.speech_started`, live transcript, the Gemini voice picker and the Deepgram think/speak/listen pickers (including the custom passthrough), the tunnel toggle and the four developer snippets, with the model qualified as `<provider>/<model>` as upstream requires. `LiveCaptionExampleCard.svelte` plus `lib/subtitleFormatter.ts` render the live caption sample, and `lib/providers.ts` gains the `realtime` kind together with the gemini/deepgram `realtimeConfig` (default model, voice, transport, service kinds) copied from the upstream registry — so a realtime or caption connection is pickable where its siblings are, driven by registry data rather than a per-provider branch (§3.D).
- **Routes.** `SetupRoutes` now mounts both WebSocket transports on both path spellings upstream serves: `GET/POST /v1/realtime` (+ `/api/v1/...`) → `internal/handlers/realtime` handler, `GET/POST /v1/audio/live-transcriptions` (+ `/api/v1/...`) → `internal/handlers/caption` handler. `OPTIONS` on all four answers `204` with `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Headers: *`, `Access-Control-Allow-Methods: GET, POST, OPTIONS` (the preflight handler lives in `router.go`; the GET-without-upgrade protocol-info documents come from the handlers themselves, per upstream route.js).
- **Auth for a browser socket.** `middleware.ExtractApiKey` accepted a query token only when the path ended in `/stream`. Browsers cannot set headers on a WebSocket handshake, so the four upgrade paths now accept the query token too, in upstream's exact source order: query param (`apiKey`, `api_key`, `token`, `key`) → `Authorization: Bearer` → `x-api-key`. Nothing else widened: `/v1/chat/completions?apiKey=…` and every non-WS path still rejects a query token (pinned by test).
- **Rate-limit seam (highest-risk edit).** `RequireRateLimit` releases the per-key concurrency slot in a `defer`, so a hijacked socket held the slot for the whole session — one idle voice call could lock its key out. WebSocket handshakes on the four upgrade paths (GET + `Upgrade: websocket`) now take an RPM stamp but **no** concurrency slot; the handshake request-rate limiting is kept, and a plain GET on the same paths (the info document) still holds the slot. Pinned by tests that hold the slot on a normal route, open a socket, and prove the normal route stays blocked.
- **Dashboard WS model probe.** `dashboard.ProbeWebSocketModel` ports upstream `ping.js` `probeLocalWs` (`:58-106`) + the `realtime`/`liveCaption` branch (`:218-230`): dial the gateway's own socket (`/v1/realtime?model=<model>&voice=Puck` for `realtime`, `/v1/audio/live-transcriptions?model=<model>&language=id&encoding=linear16&sample_rate=16000` for `liveCaption`, both with `apiKey=<key>`), succeed on the first `session.created` / `ready` frame, fail on an `error` frame, 15 s timeout, always close. `WSProbeResult` carries the same `{ok, latencyMs, error}` shape the SPA's Test chip already renders.
- **Socket publication (race).** Both adapters publish their upstream socket through a single `atomic.Pointer` instead of a plain field: the client read loop starts as soon as the upgrade completes, so a `session.update` arriving while the dial is still in flight could otherwise observe a nil or half-published connection with no ordering between the write and the read. Caught by CI's race detector, which cannot run on the authoring machine (no C compiler).
- **Deliberate divergences from upstream:** (1) upstream's close codes are kept verbatim — `4400` unsupported provider / invalid model, `4401` unauthorized, `4500` upstream connect failure, `4502` upstream setup failure, `4503` no credentials / all accounts rate-limited — so clients can keep differentiating them; (2) **no mid-session account rotation for sockets**: a socket session resolves one connection at dial time and never rotates or re-resolves mid-session, and it does not dial through a connection's proxy pool (upstream behaves the same — rotation is a per-request decision, and a socket pins one account for its lifetime); (3) on the caption route an unauthorized handshake is refused by `middleware` before the socket is established (HTTP status) rather than as an in-socket `4401` frame, because the Go auth seam runs at the handshake — the realtime route keeps the in-socket `4401` close code, and the end-to-end test pins the caption behaviour.
- **One blocker fixed on the way (disclosed, outside the lane-D file list):** `middleware.RequestLogger`'s `statusWriter` did not forward `http.Hijacker` (the same class of gap its `Flush` forwarding fixed for SSE), so gorilla answered **every** WebSocket upgrade on the production middleware stack with a 500 — no route on the wave could ever upgrade. Added a `Hijack()` passthrough in `internal/middleware/logging.go`; pinned by `TestRateLimit_RequestLoggerPreservesHijacker` and by both end-to-end tests.
- **Dependency bump (GO-2026-4550).** `github.com/cloudflare/circl` v1.6.2 → v1.6.3. It is an indirect dependency reached through `bogdanfinn/fhttp` → `bogdanfinn/utls` in the proxy executor, and `govulncheck` — the lint job's second step, which this PR is the first to reach, because golangci-lint used to fail before it — reports the vulnerability against v1.6.2 on `main` too, so the PR could not go green without it. `go.mod`/`go.sum` carry only that version change and `go mod tidy` leaves the rest of the graph alone; all five `CROSS_TARGETS` still build with `CGO_ENABLED=0` (§4.F).
- **Branch images are published to GHCR.** A new `docker-publish` job pushes every same-repo branch build to `ghcr.io/<owner>/<repo>` (tagged with the sanitized branch name and the commit sha), so an image can be pulled instead of rebuilt. It is a separate job on purpose: a required status check is matched by its job name, so widening the existing `docker` job would have left a required check that can never report. Pushes are skipped for fork PRs, whose token is read-only.
